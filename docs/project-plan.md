## Product model

The site is a practical workflow hub, not a loose calculator catalogue:

```text
Source
→ Storage
→ Pumping
→ Pipes and transport
→ Treatment
→ Use
→ Drainage, reuse or discharge
```

Every workflow should lead from evidence to a calculation or decision, then to interpretation, verification and the next system step.

## Technical and editorial model

- English-language, global audience
- Static HTML, CSS and vanilla JavaScript
- GitHub Pages and Cloudflare
- Hydraulic Field Bench design system
- SI-first calculations with relevant US customary support
- Primary, authoritative sources for health, chemical, safety and regulatory topics
- Explicit assumptions, limitations and jurisdictional variation
- No claim of formal engineering approval, potable safety or regulatory compliance

## Prioritisation

The initial plan ranked clusters using search suitability, publicly observable demand evidence and competitive opportunity. These planning scores are directional and are not presented as verified search volume.

The first wave is now complete. Any second-wave expansion—such as stormwater and flooding, building water management, wastewater or process water—must be justified by indexing, usage, query, error and maintenance evidence. Do not publish empty future routes.

## Release principle

New public work must include:

1. A distinct user task and non-duplicate route.
2. Sourced formulas or decision logic.
3. Safety and regulatory boundaries appropriate to the topic.
4. Independent calculation or rules-path tests.
5. Complete static, navigation and responsive browser QA.
6. Updated inventory, sitemap, machine-readable files and handover.
